## [Claude Code 发送 33k 令牌开销，OpenCode 仅 7k](https://systima.ai/blog/claude-code-vs-opencode-token-overhead) ⭐️ 8.0/10

一项实证研究发现，Claude Code 在处理提示前会发送约 33,000 个令牌作为开销，而 OpenCode 仅发送约 7,000 个令牌，表明两种代理编码工具在缓存策略和框架令牌使用上存在显著差异。 令牌效率直接影响使用 AI 编码工具的开发者的 API 成本和响应速度，因此这一发现对预算规划和工具选择具有实际意义。这场争论还揭示了当工具提供商从令牌消耗中获利时可能存在的利益冲突。 该研究记录了每个编码工具与 Anthropic 端点之间的所有请求并捕获了使用块；作者在帖子末尾承认了一个注意事项。一些社区成员指出，子代理可能大幅增加令牌消耗，并且不应将提示简洁性与整体效率混为一谈。

hackernews · systima · 7月12日 18:25 · [社区讨论](https://news.ycombinator.com/item?id=48883275)

**背景**: 像 Claude Code 和 OpenCode 这样的代理编码工具使用 AI 代理，以最少的人工干预自主规划、编写、测试和修改代码。这些工具在处理用户任务前会发送系统提示和上下文（令牌开销），这部分开销会增加 API 成本。Claude Code 是 Anthropic 的专有工具，而 OpenCode 是开源替代方案。该研究通过拦截 API 调用来比较它们的令牌开销。
