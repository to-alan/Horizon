## [actions/checkout v7 blocks fork PR code by default](https://github.com/actions/checkout) ⭐️ 8.0/10

actions/checkout v7 now refuses to check out fork pull request code by default when the workflow is triggered by `pull_request_target` or `workflow_run`, preventing 'pwn request' vulnerabilities. Users can opt in by setting `allow-unsafe-pr-checkout: true` after reviewing the risks. This is a critical security update for one of the most widely used GitHub Actions, protecting countless CI/CD workflows from credential theft and secret exposure. It addresses a common misconfiguration that has been exploited in real-world attacks. The v7 release also migrated `actions/checkout` to ESM (ECMAScript Modules) and updated dependencies with security fixes. The `pull_request_target` and `workflow_run` triggers run with elevated permissions, making fork PR checkout risky.

rss · GitHub Trending - Daily · Jul 12, 01:33

**Background**: The 'pwn request' vulnerability arises when a workflow triggered by `pull_request_target` or `workflow_run` checks out and executes code from a fork. These triggers run with the base repository's `GITHUB_TOKEN`, secrets, and runner access, allowing an attacker to submit a malicious PR that exfiltrates sensitive data. Many workflows inadvertently use these triggers without proper isolation, leading to security breaches.
